# 规范文档审查提示模板

在分派规范文档审查子代理时使用此模板。

**目的：** 验证规范是否完整、一致且准备好进行实现规划。

**分派时机：** 规范文档已写入 docs/superpowers/specs/

```
任务工具（通用）：
  description: "审查规范文档"
  prompt: |
    你是一个规范文档审查员。验证此规范是否完整且准备好进行规划。

    **要审查的规范：** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查要点 |
    |----------|------------------|
    | 完整性 | TODOs 占位符、"TBD"、不完整的部分 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰度 | 需求足够模糊而导致有人构建错误的东西 |
    | 范围 | 足够集中于单个计划——不涵盖多个独立子系统 |
    | YAGNI | 未请求的功能、过度工程化 |

    ## 校准标准

    **只标记在实现规划过程中会导致实际问题的问题。**
    缺失的部分、矛盾、或足够模糊以至于可以有两种不同解释的需求——这些都是问题。轻微的措辞改进、风格偏好和"比其他部分不那么详细的章节"不是问题。

    除非有严重的缺陷导致计划有缺陷，否则予以批准。

    ## 输出格式

    ## 规范审查

    **状态：** 批准 | 发现问题

    **问题（如有）：**
    - [章节 X]：[具体问题] - [为什么它对规划重要]

    **建议（ advisory，不阻止批准）：**
    - [改进建议]
```

**审查员返回：** 状态、问题（如有）、建议
